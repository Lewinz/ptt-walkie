# 黑客松实施计划

在 [requirements.md](requirements.md) 的基础上，确定黑客松期间可交付、可演示的范围。

## 关键决策

| 问题 | 决策 | 理由 |
|---|---|---|
| 路线 A 还是 B | **B 的服务端 + 浏览器模拟设备**，固件侧给出协议与接入说明 | 现场没有量产硬件也能演示实时对讲；协议按 ESP32 能力设计，后续固件直接对接 |
| 语言 | Go 单二进制（控制面 + 语音面 + 管理面同进程） | 部署简单，WebSocket 转发性能足够，ESP32 生态常见 |
| 语音传输 | WebSocket 二进制帧，Opus 16kHz / 60ms | 与 xiaozhi 生态一致；浏览器用 WebCodecs 编解码 Opus |
| MCP 传输 | Streamable HTTP（`POST /mcp`）+ 可选的「MCP 接入点」WebSocket 反连 | 灵矽 / xiaozhi 智控台两种接入方式都覆盖 |
| 设备身份 | `X-Device-Id` 头、`/mcp/d/{device_id}` 路径、工具参数 `device_id` 三选一 | 平台是否携带设备 ID 尚未确认，多路兜底 |
| 存储 | 内存 + JSON 快照持久化；录音落本地目录，可切七牛 Kodo | 黑客松零依赖可跑，留扩展口 |
| AI 能力 | OpenAI 兼容接口（默认七牛 AI 大模型推理 `https://api.qnaigc.com/v1`），未配置时降级 | 转写 / 摘要 / 关键词预警可插拔 |

## 演示脚本

`make demo` 启动（预置演示群 + 回声测试机器人），然后：

1. 打开管理端建「京沪线车队」，得到房间号与二维码。
2. 两个浏览器标签（模拟两台设备）扫码 / 输入房间号入群。
3. 按住 PTT 讲话，另一台实时播放；同时按下时后者听到「嘟」提示音（抢麦失败）。
4. 对模拟器里的 AI 助手说「切到老乡群」（或用灵矽智能体 / MCP Inspector 调用 `switch_group`），设备端实时切换频道并播报。
5. 调用 `summarize_missed`，得到错过消息的摘要；转写命中「事故」时设备端先播预警音。
